Sign in to Proxmox

The upgrade shell needs a root@pam login. Enter the root password; the dashboard signs in to the host itself and relays the console to a new tab. The password and the Proxmox session stay on the dashboard server.

Switch to an API token

The dashboard signs in to as root@pam once more and sets up its own account:

  1. Role PMM with only what the dashboard uses:
  2. User pmm@pve with a long random password that is set and thrown away. Nobody can sign in to the web UI with it; only its token works.
  3. PMM on / for pmm@pve (all nodes, guests and storage).
  4. An API token for pmm@pve, stored encrypted in the dashboard only.
  5. A check that the token sees the same nodes and guests as root@pam. Only then the host switches to the token and the stored root@pam credential is removed. If anything fails, what was created is removed again.
This host signs in with the root@pam API token , which has full root access. The switch uses it, then removes it from the host.

Afterwards: VM consoles open on the token. The node terminal and container consoles ask for the root password when you open them (it isn't stored). Updates: Update node (update agent), or SSH if it's set up for this host.

Set up updates on

A small agent on the node installs updates when the dashboard asks, so updating takes one click and no root password. It opens no port and connects nowhere: the dashboard leaves a signed request in the node's notes over the Proxmox API and reads the agent's output from the node's log. Only requests signed by this dashboard (key ) are accepted, and the only thing it can do is install pending updates.

  1. Open terminal on this node (asks for the root password one last time).
  2. Copy the block below, paste it into the terminal (Ctrl+Shift+V) and press Enter.
  3. Check agent. On a cluster, repeat for each node.
